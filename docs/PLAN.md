# 首版实现方案

版本：v0.1 / 2026-09-26。状态：待实现。

## 1. 目标与判断标准

让用户导入本地英语音视频与已有字幕，在连续延迟和片段核对之间比较体验。
中文译文可选，不是启动条件。首版成功意味着功能正确、交互能用、日志可解释；不意味着证明听力进步。

假设：用户能提供可在目标浏览器播放的本地文件、与音频基本匹配的字幕。
没有真实材料时，合成媒体只能证明工程行为，不能证明学习效果。

## 2. 范围

### 必须做

- 本地媒体导入；SRT 和本项目 cues.json 导入、明确的校验错误。
- 连续延迟：D=0～3 秒，步长 0.1 秒，默认 1 秒；全部以媒体时间计。
- 片段核对：从片段开头听到结束，原文此前隐藏，结束即暂停显示。
- 按需显示/隐藏译文；重听指定片段；标记没听懂。
- 独立的进度、播放暂停、音量控制；明确的操作目标与状态提示。
- IndexedDB 本地事件记录，JSONL 导出，刷新后可导出此前已提交的记录。
- 文本级字幕安全、本地运行、自动测试、人工测试说明。

### 明确不做

- 逐词 A、连续播放版 C、暂停后计时延迟、自适应延迟、倍速。
- ASR（自动语音识别）、LLM（大语言模型）翻译、GPU/CUDA、音频提取或下载。
- 译文生成/合并工具、字幕编辑、SRT/VTT 导出、WebVTT 导入、字幕同步校正。
- 说话人识别、实时捕获、浏览器扩展、DRM 内容处理、桌面壳、账号、远程部署。
- 重叠字幕排版、素材库、学习成绩打分、实验分析面板、完整全文预览。

这是范围决策，不表示这些功能技术上不能做。后续只有用户确认需求后才扩展。

## 3. 输入与加载

- 接受一个本地媒体文件和一个字幕文件；首次两者通过校验并确认后才启用练习。初始模式为 B、D=1000ms、位置 0、暂停，不自动播放。
- 先支持 Windows Chrome/Edge 桌面端，1 倍速。音频文件也要可使用同一练习流程。
- 建议验证用媒体为 H.264/AAC MP4，以及 PCM WAV 或 MP3 音频；真实解码失败时明确提示，不只凭扩展名判断。
- 文件选择器读取媒体，object URL 提供给媒体元素。页面服务只提供应用资源。
- 同一个文件再次选择也要可重新加载；替换成功后释放旧 object URL。
- 两份输入作为一对待确认的素材：有现有会话时先暂停，提示重新载入会新开会话，不删除历史日志。
- 用户完成新的一对选择、确认且校验成功后才替换现有数据；取消或无效输入保留原会话并保持暂停。
- JSON 的 media_id 仅是逻辑名称，不证明它与所选媒体匹配；显示文件名、条目数、字幕范围、媒体时长，请用户确认。
- 用媒体真实 duration 检查最后一个 end_ms。超过 duration + 100ms 拒绝；不超过该容差只按边界精度误差接受，不改写原时间戳。
- 拒绝空轨、时间倒置、乱序、重叠或重复 ID。报出条目 ID/索引与原因，不静默排序/截断/合并。
- 不自动发现媒体内嵌字幕，不允许它与自绘字幕同时提前泄露原文。

## 4. 确定的播放语义

### 4.1 通用规则

- 原始时间区间为左闭右开：[start_ms, end_ms)。相邻条目可以首尾相接。
- audioCueId 按媒体时间查询；静音间隙为 null。
- displayCueId 只表示实际可见原文，隐藏时为 null；不能拿它替代音频位置。
- actionCueId 明确显示为“操作目标：第 N 条”，不要统称“当前句”。正常 B 取显示条目；片段待播放/聆听/核对和隔离重听取锁定的 focusedCueId；片尾补看取选中条目。
- 译文首次隐藏。换条目、seek、重听、切模式、改延迟、换素材均清除已揭示状态。
- 缺译文时“译文”按钮禁用并解释“此条无译文”，不能让整条字幕消失。
- 播放速度固定 1。标签页隐藏时暂停媒体，返回不自动续播；记录原因以免后台计时漂移影响验收。
- 第一版不提供字幕全文列表，防止意外预读。片尾补看区是明确的例外。

### 4.2 连续延迟（B，非隔离重听阶段）

令 t 为媒体时间毫秒、D 为学习延迟毫秒：

```text
audioCue = findCue(t)
displayCue = findCue(t - D)
```

findCue 在 [start, end) 中查询，不按单词调度。原显示区间整体平移为 [start+D, end+D)。
间隙显示空白，不把上一条一直留在屏幕上。actionCueId = displayCueId。
没有显示条目时禁用译文、重听、没听懂按钮；不偷偷操作另一个条目。
手动暂停冻结当前位置及对应字幕；调整 D 后立即重算并隐藏译文，不改变播放进度。

**片尾：**自然 ended 后进入有标签的“片尾补看”，不是延长媒体时钟。
列出 end_ms + D > duration 的条目（包括只显示了一部分和完全没来得及显示的条目），按原顺序展示原文，译文仍逐条隐藏。
默认操作目标为列表首条，允许点击选中另一条。D=0 且没有尾部条目时只显示“播放结束”。
如果仅在时长容差范围内超界且 D=0，也纳入补看。用户 seek 到片尾或显式 seek 越过它不是自然 ended，不自动弹出补看。
B 已到媒体末尾时，主按钮改为“从头播放”；主动点击才清空补看/译文、seek 到 0 后播放，不依赖浏览器隐式重播。

### 4.3 片段核对（受限 C，D=0）

- 切入时暂停，选当前位置所在条目；如果在间隙则选下一个；在最后一条之后则显示“已到末尾”。
- 第一次按播放，从目标 start_ms 开始，而不是从条目中间开始。
- 听的过程中原文、译文均隐藏，只显示“正在听第 N 条”。
- 到 end_ms 时暂停，定位回该边界，显示该条原文，译文仍隐藏。若末条 end_ms 在允许的媒体时长容差内略超尾部，native ended 也作为该片段完成，定位不超过媒体 duration；不会永远等一个无法到达的时间。
- 再按播放/继续，选择下一条、从其 start_ms 播放；片段之间的空白在这个模式下有意跳过。
- 最后一条核对后，“继续”显示完成，不再次自动播放；仍可重听最后一条。
- 原始字幕条目不保证完整句子，界面和文案一律使用“片段”，不承诺语法句末。
- 在此模式延迟滑块禁用，明确标注“听完即暂停，延迟不适用”；保留 B 的 D 值供切回使用。

### 4.4 重听：统一为一次隔离的片段播放

这是一个显式的产品取舍：重听不延续连续播放的字幕偏移，而是专注核对所选片段。

1. 捕获 actionCueId；该 ID 不随 seek 中间产生的音频/显示变化而改变。
2. 清除原文与译文，seek 到该条 start_ms，等定位完成后播放到 end_ms。
3. 暂停并显示目标原文；译文仍隐藏。原所属模式不变，但此时显示“重听核对”。
4. 在 B 中按继续，从目标 end_ms 恢复 B 的普通播放，不跳回按重听之前的位置。若已到媒体末尾，进入片尾处理，不直接调用 play 导致隐式从头重播。
5. 在片段核对中按继续，进入下一条；反复按重听始终只播放该条一次，不叠加调度器。

重听期间禁用 D 调整；允许手动暂停/继续这一次重听。用户拖动进度则取消这次专注播放。
片段模式的最后一条完成时，native ended 只用于完成该片段，不同时触发 B 的补看或重复完成事件。

### 4.5 seek、模式切换与异步事件

- 用户 seek：先暂停、取消旧目标/回调、清除译文。
  - B：定位后重新计算字幕，保持暂停，用户再按播放。
  - 片段核对：选落点所在/下一个条目并显示“待播放第 N 条”；下一次播放从该条起点开始。
- 切模式：暂停、取消重听与旧边界处理、清除译文，不自动续播。
- 普通用户暂停不是“片段听完”；不能揭示片段核对中的原文。
- 快速连续 seek、换素材、切模式必须使旧回调失效；可用递增操作版本，不为此建立通用任务框架。
- 播放失败、解码失败不能标记成正在播放；显示可恢复的错误状态。

## 5. UI 与快捷键

单页中文界面：导入区 → 媒体区 → 固定原文/译文区 → 控制区 → 本地日志状态。
不做营销首页、仪表盘或大面积装饰；核对文字与当前状态优先。
字幕区预留高度，译文展开不推动主要按钮跳动；长文本换行，不截断。

| 操作 | 快捷键 | 语义 |
| --- | --- | --- |
| 播放/暂停/继续 | Space | 按当前阶段执行；按钮标签同步变化 |
| 显示/隐藏译文 | T | 仅作用于当前可见原文的操作目标 |
| 重听片段 | R | 对 actionCueId 执行 4.4 |
| 标记没听懂 | U | 写一次显式操作事件，给短暂反馈 |

- 片段核对的聆听阶段：R 可用；T/U 禁用，原文未出现不能偷看译文。
- 无操作目标时，R/T/U 禁用。键盘输入不能绕过按钮禁用条件。
- 忽略 key repeat，忽略 Ctrl/Alt/Meta 组合；输入框、滑块、选择器、可编辑区中不触发全局快捷键。
- 原生按钮上的 Space/Enter 保留按钮本身行为，不能同时触发全局 Space。
- 核心操作均有可点击按钮、文字标签、可见焦点；不要求用户记快捷键。
- 自有进度条统一走控制器，不依赖媒体原生控制条绕过状态逻辑；不要求首版做全屏。

## 6. 架构与模块边界

建议使用 Vite + TypeScript + 原生 DOM/CSS，不需要服务端。

```text
src/
  subtitles/     SRT/JSON 解析、校验、规范化
  timeline/      findCue、延迟查询、尾部集合等纯函数
  player/        媒体适配、练习阶段、seek/重听/边界处理
  events/        事件封装、IndexedDB、JSONL 导出
  ui/            页面、按钮、键盘、状态呈现
```

这是职责建议，不要求为每个职责建很多类。
不要全局复用一个含糊的 currentCue；参考 DATA_CONTRACT 的 ID 分工。

- 连续播放按最新媒体时间推导视图。requestAnimationFrame 可用于前台刷新；timeupdate 只能作为补充，不承诺精确频率。
- 片段边界采用同一个媒体时钟观测；单次活动目标，暂停后校正位置，不为全轨创建 setTimeout。
- 媒体事件处理须考虑 seek 期间与操作版本；对 ended 明确区分正常结束/片段结束。
- 真实 HTMLMediaElement 与测试用媒体适配分离：模拟验证状态，真实播放验证整合。
- 日志队列按事件顺序串行提交，显示“已保存/待保存/保存失败”；别把 enqueue 当保存成功。

## 7. 实现顺序与每步出口

### M1：导入、校验和时间核心

交付：脚手架、输入校验、fixtures 单测、纯时间函数。
出口：AC-01～04、AC-07 的逻辑部分通过；不需要先画完整页面。

### M2：真实媒体与连续延迟

交付：本地媒体加载、B、seek/暂停/D 修改、片尾补看、清晰的目标 ID。
出口：AC-05～10、AC-18、AC-21 的对应部分通过。

### M3：核对与重听

交付：片段核对、隔离重听、译文开关、U、快捷键和操作取消。
出口：AC-11～17 的状态测试及浏览器用例通过。

### M4：持久化与完整交付

交付：日志与导出、失败提示、真实播放与人工验收、README、VERIFICATION。
出口：AC-01～24 的结果全部明确，达到 ACCEPTANCE 的完成门槛。

不能因为没有用户真实视频而停在空页面：使用 fixtures 对应的合成媒体完成工程测试，但标明真实学习试用尚未验证。

## 8. 后续扩展门槛（本轮不实施）

- 用户觉得现有字幕体验有价值但素材缺字幕 → 再做离线转录、词级时间戳与分句。
- 有字幕但缺中文影响试用 → 再做离线翻译与 ID 完整性检查。
- 确认想逐词先听后看 → 再定义 A 的词边界、换行和保留策略。
- 明确主要材料是直播/会议 → 单独评估 Windows 捕获与流式服务，不扩展当前播放器任务。

## 9. 技术依据与边界

本方案核对过 MDN 的 File API、HTMLMediaElement timeupdate、IndexedDB 文档及 Vite 官方入门文档。
这些资料支持本地文件输入、浏览器持久化、刷新事件限制与开发脚手架选型；不会保证用户媒体编码兼容或机器性能。
项目规则（D 范围、暂停策略、容差等）是本次明确选择，不是声称存在科学上的最佳值。
