# Delayed Listening Lab｜延迟字幕听力实验

状态（2026-09-26）：**v0.1.0 原型已实现，工程自动检查通过；Windows 真实语音人工试用待验证。**
本轮实际结果：类型检查、76 个单元测试、14 个浏览器端到端测试、生产构建通过。
完整验收尚未完成，逐项证据与限制见 [docs/VERIFICATION.md](docs/VERIFICATION.md)。

## 要验证什么

对已有字幕的本地英语材料，比较两种体验：

1. **连续延迟 B**：原文字幕整体后移，先听再看；延迟为 0 时即正常字幕。
2. **片段核对**：听一个字幕片段，暂停后看原文，按需看中文，再继续。

第一版只验证播放器交互，不证明长期听力提升，也不构建实时字幕平台。
字幕条目不保证是完整句子；没有可用字幕的材料暂不能处理。字幕内嵌在视频里（内封文本轨或烧录进画面的硬字幕）也不能直接用，需先在外部提取成 `.srt` 再导入，见下方前提说明。

## 安装与运行

在本项目目录执行。需要 npm，以及符合 `package.json` 的 Node：
`^22.12.0 || ^24.0.0 || >=26.0.0`。本轮实测为 **Node 24.18.0 / npm 11.16.0**；其他版本未逐一测试。
依赖版本固定在 `package-lock.json`，使用 npm，不另建锁文件。

```bash
npm ci
npm run dev
```

浏览器访问固定地址 **`http://127.0.0.1:5173`**。仅监听本机，端口占用会报错，不会悄悄切换端口。
安装步骤是复现指引；本轮检查使用已有依赖，没有再次执行 `npm ci`。

### WSL → Windows 浏览器

WSL（Windows Subsystem for Linux，Windows 的 Linux 子系统）中进入本目录运行上述命令，保持终端服务运行，再在同机 Windows Chrome 或 Edge 打开 `http://127.0.0.1:5173`。
文件选择器属于浏览器所在系统：在 Windows 浏览器里选择自己有权使用的本地音视频及配套字幕。

本轮自动测试在 WSL 内的 Chromium 运行，**尚未实际验证 Windows 浏览器访问与听感**。
如果无法打开，先检查服务终端是否成功启动、端口是否被其他服务占用，再在 WSL 内用 `curl -I http://127.0.0.1:5173` 确认本地服务；Windows 端可用 `Test-NetConnection 127.0.0.1 -Port 5173` 检查连接，并检查自己的 WSL 本机转发设置。
不要为此绑定 `0.0.0.0`、开放公网、擅改防火墙或父级配置。

## 开始练习

1. 选择一个音视频与一个 `.srt` / `.json` 字幕文件，点击“检查配对”。核对名称、时长、条数与字幕范围，再“确认配对并开始会话”。校验不能替你判断内容是否同步。
2. 初始为连续延迟 B、延迟 **1.0 秒**、位置 0、暂停。按“播放”后开始；延迟可调 **0～3 秒，步长 0.1 秒**，只改显示，不改字幕原时间。仅支持 1 倍速。
3. 切换“片段核对”会暂停，选择落点所在条目或下一条。按播放从该条起点听，听完即暂停并显示原文；途中手动暂停不会揭示。此模式延迟不生效，但保留 B 的参数。
4. “显示译文”只作用于可见原文的操作目标；缺译文时会说明并禁用。“没听懂”记录该目标并给出反馈。
5. “重听片段”锁定界面标明的操作目标，只播放其原始起止范围，途中隐藏文字；结束显示原文、译文仍隐藏。B 中按继续从该片段终点恢复，不返回重听前的位置；片段核对中继续到下一条。
6. 拖动进度、切模式或重新导入会暂停并取消旧的重听；无待播放片段时控件及快捷键均不会伪造完成事件。片段核对最后一条听完并核对后，“继续”才完成练习，仍可重听。
7. B 自然结束时提供“片尾补看”，可选择延迟显示未完成的条目进行 T/R/U 操作；直接拖到末尾不自动补看。“从头播放”需主动触发，不会自动重播。

字幕区保留原文/译文各自空间；长文本完整换行，可聚焦后滚动阅读。标签页隐藏会暂停，返回不会自动播放。
换素材只有新的一对通过校验并确认才生效；取消或坏输入保留原会话并保持暂停，不删除历史。

| 操作 | 快捷键 |
| --- | --- |
| 播放 / 暂停 / 继续 | Space |
| 显示 / 隐藏译文 | T |
| 重听操作目标 | R |
| 标记没听懂 | U |

按钮与快捷键共享规则，无目标不能操作。长按不重复计数；输入框、滑块、选择器、可编辑区域不触发全局快捷键；按钮上的 Space / Enter 保留原生按钮行为。也可用 Tab、方向键及 Enter 操作页面。

## 输入与隐私边界

- **媒体编码由浏览器实际解码决定**，不是扩展名正确就一定支持。本轮分别实播 H.264/AAC MP4 和 PCM WAV；MP3 可选择但本轮未实测，不承诺所有 MP4/音频编码。
- 只接受 **UTF-8 SRT 子集**或符合 [数据契约](docs/DATA_CONTRACT.md) 的 cues.json。SRT 不生成译文；JSON 中文可选。空轨、重复 ID、倒置/乱序/重叠时间、错误字段均拒绝，不静默排序修复。
- **不解析视频内嵌字幕**：浏览器读不到 MP4/MKV 内封文本轨，硬字幕又是画面像素。内封字幕请先用 ffmpeg 提取，例如 `ffmpeg -i input.mkv -map 0:s:0 subs.srt`；硬字幕需外部 OCR 工具转成 SRT，再作为字幕文件导入。
- 字幕最后结束时间超过媒体时长 **100ms 以上拒绝**；容差内保留原时间，不等于完成同步校正。
- 媒体用文件选择器和 object URL（浏览器本地文件引用）加载，替换后释放旧引用；不上传，不把媒体或字幕正文写入 IndexedDB（浏览器本地数据库）。正文按纯文本显示，不执行其中的 HTML。
- 不做逐词模式、转录、自动翻译、字幕编辑、下载、系统音频捕获、Netflix/直播、账号、云端服务或部署。

## 日志保存与导出

事件位于当前浏览器、当前站点来源的 IndexedDB：数据库 **`delayed-listening-lab`**，对象仓库 **`events`**。
**固定使用同一个地址**：`localhost` 与 `127.0.0.1` 是不同站点来源，换端口、浏览器或配置档也不会共享这里的记录。

- “导出本次会话”导出当前已提交记录；“导出全部会话”包含历史会话，刷新后无需重选媒体即可导出历史。
- 格式为 JSONL（JSON Lines，每行一个 JSON 对象），按会话和事件序号排序；导出会等待已入队记录的提交快照，不把后来的操作混入该快照。
- 页面区分“待保存 / 已保存 / 保存失败”。失败时先下载“未保存记录”，也可点击“重试保存”；失败记录仅留在本页内存，**刷新或关闭前必须导出**，普通历史导出不代表未保存部分已被持久化。
- 记录不含音视频或字幕正文，但会话元数据**包含媒体文件名**；分享前检查隐私。浏览器清理站点数据可能删除历史，本地存储不等于备份。
- 不保存完整播放器状态；刷新后需重新选择并确认素材，新开会话，不自动恢复文件权限或播放。

## 测试与工程样例

[fixtures/README.md](fixtures/README.md) 描述 7 条虚构字幕及精确时间表。
浏览器端到端测试（E2E，End-to-End）需本地 Chromium 和工程媒体：

```bash
# 首次准备：需要联网下载 Playwright 配套浏览器
npx playwright install chromium
# 需要系统已安装 ffmpeg；只生成缺少的文件，保留已有同名文件
npm run fixtures:media

npm run typecheck
npm test
npm run test:e2e
npm run build
```

Playwright 配置使用 `channel: chromium`，需安装完整 Chromium，不要只装 `--only-shell`。
若提示缺 Linux 系统库，按错误提示检查环境并在得到授权后安装；不要把启动失败记为通过。
E2E 自动启动本机开发服务；如果已有本项目服务，可复用。请勿让无关服务占用 5173。

工程媒体是 `generated/timing-20s.wav`、`generated/timing-20s.mp4`，由 ffmpeg 生成 20 秒 440Hz 提示音（视频另有纯色画面），与 `fixtures/basic.cues.json` 或 `basic.en.srt` 配对。
**没有英语语音，真实播放通过不等于真实英语材料人工试用通过。** 不下载用户或第三方媒体。

每次 E2E 默认生成唯一运行目录 `test-results/<时间戳-随机标识>/`，包含 `results.json` 和逐测试 `artifacts/`；失败保留截图与 trace，后续运行不覆盖历史。
`DELAYED_LISTENING_E2E_RUN_ID` 是可选的运行标识覆盖值，手工设置时须使用新的唯一值，否则对应目录可能被测试运行器清理。
